# 四个人只需要统一这些

所有人拿到相同的完整项目，在自己的目录开发。公共基础由成员四维护；需要新字段时把具体修改告诉成员四，不要自己建立另一套数据表。

## 1. 技术和分工

Python 3.13、Django 5.2、Django 模板、普通 HTML/CSS。开发 SQLite，整合并发测试 PostgreSQL。没有独立前端项目、不引入 Vue/React/JWT，不需要各自运行四个服务。

| 目录 | 主人 | 可以修改的范围 |
|---|---|---|
| accounts/ | 成员一 | 本模块视图、表单、路由、模板、测试 |
| items/ | 成员二 | 本模块视图、表单、查询/服务、模板、测试 |
| bookings/ | 成员三 | 预订服务、视图、命令、模板片段、测试 |
| moderation/ 及其他公共文件 | 成员四 | 管理员模块、配置、公共模型/迁移/样式、CI |

每个模块已加入总路由和 INSTALLED_APPS。个人模板放 `自己的模块/templates/模块名/`，继承 `base.html`；个人 CSS/JS 放 `自己的模块/static/模块名/`，用 base 的 scripts 区块加载。公共样式已有 button/panel/grid/notice 等类，优先复用。

## 2. 统一数据模型（以 core/models.py 为准）

| 模型 | 字段 |
|---|---|
| Django User | username、password 哈希、first_name（昵称）、is_staff（管理员）；不建第二个 User |
| Listing 物品 | seller、title(60)、description(1000)、price(Decimal，0—99999.99)、category、campus(40)、meeting_place(100)、status、created_at、updated_at |
| Reservation 预订 | UUID id、listing、buyer、UUID request_key、status、expires_at、buyer_confirmed_at、seller_confirmed_at、created_at、updated_at |
| ModerationLog | actor、listing、reason(200)、created_at；成员四维护 |

导入示例：`from core.models import Listing, Reservation`；获取用户用 `get_user_model()`。price 用 Decimal，不用 float。分类值为 BOOKS/DIGITAL/DAILY/OTHER；campus 是文字，不依赖学校接口。所有物品只代表一件实物。

Listing 状态：AVAILABLE 可预订、RESERVED 已预订、COMPLETED 已完成、OFF_SHELF 已下架、HIDDEN 已隐藏。Reservation 状态：ACTIVE、CANCELLED、EXPIRED、COMPLETED、VOID。

数据库已有“每件物品最多一个 ACTIVE”和“同买家 request_key 不重复”约束。公共模型修改只由成员四统一生成迁移。各人不得在自己模块新建 Listing/Reservation 或直接改数据库结构。

## 3. 统一业务规则

- 普通学生同时可以买和卖；不能预订自己的物品；管理员通过服务端 is_staff 判断。
- 成员二负责 AVAILABLE ↔ OFF_SHELF；成员三负责 AVAILABLE → RESERVED → COMPLETED，以及取消/到期返回 AVAILABLE；成员四负责隐藏并将有效预订置 VOID。
- RESERVED 物品不能改价、编辑或下架。COMPLETED/HIDDEN 不提供普通恢复入口；管理员不能隐藏 COMPLETED。
- 预订成功后保留 24 小时；时长取 `settings.RESERVATION_TTL_SECONDS`，不是写死在前端。数据库用 UTC，界面上海时间。
- 双方分别确认，第二方确认才完成；单方确认不延长期限。到期时未双确认则释放。买家在到期前可取消，包括仅有一方确认的情况。
- 当前服务端时刻 ≥ expires_at 即到期。取消/确认/隐藏/下架都先在锁内检查到期。已经取消、过期、作废的预订不能被确认。
- 所有状态写入：`transaction.atomic()` 内先 `lock_listing()`，再处理 Reservation；`release_if_expired()` 供复用。先检查权限，再做可能改变数据的到期归一化；未授权请求不得改变数据库。
- 到期归一化之后的“确认失败”等业务冲突正常返回 Result，不抛异常回滚到期释放。真正数据库异常才整体回滚。
- Session 认证、POST + CSRF；用户身份取 request.user，不能接收客户端传入的 seller/buyer/admin 标志。

## 4. 页面和模块如何接起来

账号 `/accounts/login/`、`register/`、`profile/`，退出为 POST `/accounts/logout/`。

物品 `/items/`、`/items/new/`、`/items/mine/`、`/items/<数字ID>/`、`/items/<ID>/edit/`。上下架 POST 到 `take-off/`、`relist/`。成员二可用 Django 表单成功跳转、失败在原页提示。

成员三写入口已注册：POST `/bookings/reserve/<物品ID>/`（FormData: request_key=UUID）、`/bookings/<预订UUID>/cancel/`、`/bookings/<UUID>/confirm/`；列表 `/bookings/mine/`。

成员三保持 `bookings.services` 四个函数签名：`reserve(buyer,listing_id,request_key)`、`cancel(actor,reservation_id)`、`confirm(actor,reservation_id)`（都是关键字参数）、`expire_due(now=None)`。前三个返回 `core.results.Result`，最后一个返回释放数量。成功 data 至少有 reservation_id、listing_id、status、expires_at；UUID/时间转字符串。错误用 code/message。

成功返回 `{"data":{...}}`，错误 `{"error":{"code":"STATE_CONFLICT","message":"..."}}`。预订新建 201、同 key 重放 200、未登录 401、越权 403、不存在 404、状态冲突 409、字段不合法 422。当前待开发返回 501，应由成员三替换。

**成员二不用等成员三：**详情页已 include `bookings/_reserve_button.html`，卖家中心已 include `bookings/_seller_actions.html`，上下文统一叫 `listing`。成员三只改这两个片段及自己的模板标签/JS，即可接上按钮，不需要修改成员二文件。不要删除 include。

**成员三不用等成员二：**运行 seed_demo，已有用户、6 件可预订物品和一件预订物品；直接写服务测试与自己的页面即可。

## 5. 验收和整合

每人运行 README 的三条检查命令，在自己模块写测试。成员四按“注册/登录 → 发布 → 搜索 → 预订 → 取消重订 → 双方确认”检查，再验证管理员隐藏和到期。数据库约束与权限不能只靠前端按钮保证。

个人开发记录写自己目录内的 `开发记录.md`，只记录真实操作、AI 工具/模型、关键取舍、测试结果和未完成项，不另写一堆泛泛报告。课程剩余材料由成员四最后对照 PPT 汇总。
