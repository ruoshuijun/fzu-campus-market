# 福大闲置｜队友开工指南

四个人共用 [fzu-campus-market 仓库](https://github.com/ruoshuijun/fzu-campus-market)。成员四在群里确认谁负责账号、物品和预订。拿到分工后，按下面的步骤克隆、启动，然后打开自己的任务书。

## 1. 把仓库克隆到电脑

需要 Git 和 Python 3.13。先登录自己的 GitHub 账号并接受协作者邀请，这样后面才能推送分支。打开 PowerShell，进入你想存放项目的文件夹，然后执行：

```powershell
git --version
python --version
git clone https://github.com/ruoshuijun/fzu-campus-market.git
cd fzu-campus-market
```

如果已经克隆过，打开现有的 `fzu-campus-market` 目录即可。在 VS Code 或 AI 工具里打开整个目录。看到 `manage.py`，就说明你到了项目根目录。

## 2. 先在本机跑起来

在项目根目录执行下面的命令。创建虚拟环境、安装依赖和生成演示数据通常只在首次启动时做。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py runserver
```

打开 [http://127.0.0.1:8000/](http://127.0.0.1:8000/)。演示账号有卖家 `student1`、买家 `student2` 和管理员 `admin`，密码均为 `DemoPass123!`。大家本机用 Python 自带的 SQLite。数据库文件由迁移命令生成，不用向队友拷贝。开发服务器运行期间保持终端开着，按 `Ctrl+C` 停止。

macOS 或 Linux 用 `python3.13 -m venv .venv`，后面把 `.\.venv\Scripts\python.exe` 换成 `.venv/bin/python`。完整环境说明见 [README](../README.md)。

## 3. 读哪几份文件，从哪项功能做起

每个人先读一遍 [公共约定](公共约定.md)，再读**自己的一份任务书**。用 AI 开发时，让 AI 同时读取根目录的 [AGENTS.md](../AGENTS.md)，并把任务书末尾的提示词粘进去。

| 分工 | 代码目录与分支 | 第一个可以做的小功能 | 任务书 |
|---|---|---|---|
| 成员一 · 账号 | `accounts/` · `feat/accounts` | 实现学生注册，验证新账号可以登录。然后补昵称修改和账号异常处理。 | [成员一任务书](成员1-账号.md) |
| 成员二 · 物品 | `items/` · `feat/items` | 用 `student1` 实现发布，检查新物品出现在列表。然后补搜索、编辑和上下架。 | [成员二任务书](成员2-物品.md) |
| 成员三 · 预订 | `bookings/` · `feat/bookings` | 用 `student2` 预订一件演示物品，检查物品变成已预订。然后补取消、到期和双方确认。 | [成员三任务书](成员3-预订.md) |
| 成员四 · 整合 | `moderation/` 和公共配置 | 用管理员隐藏演示物品，验证关联预订终止。负责处理公共接口改动和合并 PR。 | [成员四任务书](成员4-整合.md) |

三位开发成员可各自用演示账号和数据开工。账号、物品和预订使用公共数据模型，改公共字段或路由前先和成员四对齐。根目录的 [复盘报告](../retrospective.md) 和 `docs/experiment-a/` 是课程实验材料，开工时可跳过。

## 4. 在自己的分支提交

以成员一为例。第一次开分支时执行下面三行，其他成员把 `feat/accounts` 换成上表对应分支。以后接着做时，切回已经创建的分支即可。

```powershell
git switch main
git pull --ff-only
git switch -c feat/accounts
```

做完一个可运行的小功能，先按任务书检查页面和测试，再提交自己目录的改动。下面仍以成员一为例：

```powershell
git status --short
git add accounts
git commit -m "实现学生注册"
git push -u origin feat/accounts
```

推送时如果 GitHub 要求登录，用你接受邀请的账号在浏览器授权。接下来到 [仓库的 Pull requests 页面](https://github.com/ruoshuijun/fzu-campus-market/pulls)，新建 PR。目标分支选 `main`，来源分支选你刚推送的功能分支。写清做了什么、怎么验证、还有哪些部分没完成，请成员四检查。后续推送到同一分支，GitHub 会自动更新这个 PR。

第一次交付做到这一步就可以联调。成员四会结合你在 PR 里写的验证步骤检查，确认可合并后再更新 `main`。
